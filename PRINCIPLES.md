# OpenFrameworks Constitutional Principles

OpenFrameworks is guided by two constitutional principles.

## Principle 1: Everything Is a Framework

Everything can be represented as a framework.

A framework is a reusable structure for representing how something is understood, organized, governed, evaluated, operated, improved, taught, reused, or composed.

OpenFrameworks treats knowledge, systems, methods, practices, policies, controls, architectures, standards, protocols, decisions, operating models, capabilities, outcomes, and value models as frameworks or framework elements.

## Principle 2: Everything Must Be Composable Without Losing Capability

Every framework and framework element must be designed to compose with other frameworks and framework elements without losing its original capability, meaning, provenance, governance, trust, or operational usefulness.

Composition must preserve capability.

A composed framework must remain:

- understandable
- traceable
- governable
- reusable
- replaceable
- extensible
- testable
- publishable
- trustworthy
- operationally useful

## Core Statement

```text
Everything is a framework.
Everything must be composable without losing capability.
```

## Derived Rules

From these two principles, the rest follows:

- Foundation defines the framework design system contract.
- Platform operationalizes the framework design system.
- Publishing activates framework authority.
- Trust is earned through evidence.
- Governance makes frameworks accountable.
- Certification and accreditation make framework adoption reliable.
- Learning teaches organizations how to build their own framework design systems.

## Anti-Drift Rule

No framework, model, policy, pattern, implementation, or platform feature should violate either principle.

If something cannot be represented as a framework, its role in OpenFrameworks must be clarified.

If something cannot compose without losing capability, it must be redesigned before publication.
