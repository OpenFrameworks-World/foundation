# The Theory of Composition

OpenFrameworks is built on two constitutional principles:

1. Everything is a framework.
2. Everything must be composable without losing capability.

## Definition

A framework is a reusable structure that represents capability.

A composition is the governed combination of two or more frameworks into a larger framework while preserving the declared capability of each participating framework.

## Axiom 1: Framework Universality

Everything is a framework.

Everything that OpenFrameworks represents must be expressible as a framework or framework element.

## Axiom 2: Capability-Preserving Composition

Everything must be composable without losing capability.

A framework must compose with other frameworks without losing its essential capability, meaning, provenance, governance, trust, or operational usefulness.

## Law 1: Preservation

Composition must preserve capability.

If a participating framework loses its declared capability, the composition is invalid.

## Law 2: Emergence

Composition should create additional useful capability.

A valid composition should create a larger framework that is more useful than the isolated parts.

## Law 3: Identity

Composition preserves identity.

A framework may participate in a larger composition without losing its identity, provenance, ownership, version, governance, lifecycle, or trust record.

## Law 4: Interface

Frameworks compose through interfaces.

An interface may be a schema, relationship, API, workflow, policy boundary, capability contract, governance rule, semantic mapping, data exchange format, or publishing contract.

## Law 5: Contract

Composition requires a contract.

A composition contract declares what must remain true before, during, and after composition.

## Law 6: Direction

Composition has direction.

Examples:

```text
Policy Framework -> governs -> Control Framework
Capability Framework -> requires -> Implementation Framework
Evidence Framework -> supports -> Trust Framework
Publishing Framework -> activates -> Framework Authority
```

## Law 7: Compatibility

Composition requires compatibility.

Frameworks may be compatible, conditionally compatible, incompatible, or unknown. Compatibility must be declared and tested.

## Law 8: Substitution

Composition should allow substitution.

A framework should be replaceable by another framework with equivalent capability when the interface and risk profile are acceptable.

## Law 9: Recursion

A composition becomes a framework.

```text
Framework + Framework = Framework
```

Composed frameworks can themselves compose into larger frameworks.

## Law 10: Evidence

Composition claims require evidence.

A claim that frameworks compose must be supported by examples, tests, implementation records, benchmark results, governance review, or operational evidence.

## Law 11: Governance

Composition is a governed act.

A material composition must declare designer, owner, maintainer, reviewer, approver, risk owner, lifecycle state, and publishing status.

## Law 12: Context

Composition is context-bound.

A composition valid in one context may fail in another.

## Formula

```text
F1 + F2 + ... + Fn = Fc
```

Where:

```text
F  = framework
Fc = composed framework
```

A composition is valid when:

```text
Capability(Fc) preserves Capability(F1...Fn)
```

A composition is valuable when:

```text
Capability(Fc) creates additional useful capability in context
```

## Composition Is Not Aggregation

Aggregation places things together.

Composition makes them work together.

## Composition Is Not Absorption

Absorption destroys identity.

Composition preserves identity.

## Composition Is Not Replacement

Replacement substitutes.

Composition cooperates.

## Composition Loss

Every composition may introduce loss.

Loss may include capability loss, meaning loss, context loss, governance loss, provenance loss, trust loss, operational loss, performance loss, or compliance loss.

Loss must be declared.

Hidden capability loss invalidates composition.

## Composition Gain

Composition should create gain.

Gain may include increased capability, broader applicability, stronger governance, higher trust, improved traceability, reduced duplication, better decision quality, faster adoption, or higher value realization.

## Publishing

Publishing is the activation gate for composition.

A composition may exist as a draft, but it becomes authoritative only when published through a governed publishing process.

```text
Draft -> Review -> Validate -> Publish -> Adopt -> Measure -> Improve
```

## Trust

Trust does not automatically transfer through composition.

If trusted frameworks are composed poorly, the composed framework may be untrusted.

A composed framework needs its own trust record.

## Certification

Certification does not automatically transfer through composition.

A certified component may participate in an uncertified composition.

The composed framework must be certified as a composed whole if certification is claimed.

## Accreditation

Accreditation is context-specific.

A composition accredited in one organization may not be accredited in another.

## Theorem

From the two constitutional principles:

```text
Everything is a framework.
Everything must be composable without losing capability.
```

it follows that:

```text
The world can be represented as a recursively composable framework graph.
```

This graph is not merely a catalog. It is a governed design system for representing, publishing, trusting, composing, and operationalizing frameworks.

## Composition Test

Before a composition can be published, answer:

1. What frameworks are being composed?
2. What capability does each framework bring?
3. What capability must be preserved?
4. What new capability is created?
5. What is lost?
6. What interfaces connect them?
7. What contract governs the composition?
8. What evidence supports the composition?
9. Who owns and governs it?
10. What context is it valid in?
11. What can be substituted without breaking the whole?
12. What is the publishing status?
13. What trust claims are inherited?
14. What trust claims require new evidence?
15. What are the known failure modes?

If these cannot be answered, the composition is not ready to publish.

## Final Law

A composition is valid only if every participating framework preserves its declared capability, and the composed whole creates additional useful capability in a declared context.

## Core Statement

```text
Everything is a framework.
Everything must be composable without losing capability.
Composition turns frameworks into systems.
Systems create value.
```
