# Framework-Centric Foundation Model

OpenFrameworks uses a framework-centric worldview.

This does not mean every object is literally the same as a framework. It means every governed knowledge asset can be described, related, evaluated, published, and operationalized through a framework lens.

## Core Principle

```text
Everything is not the same object.
Everything is framework-addressable.
```

A capability is not a framework.
A policy is not a framework.
A control is not a framework.
A benchmark is not a framework.
A product is not a framework.
A decision is not a framework.

But each can be connected to frameworks, evaluated by framework rules, published as framework intelligence, and traced through framework-driven governance.

## Framework Lens

Every governed asset can answer:

- What framework does this belong to?
- What framework does this enable?
- What framework governs this?
- What framework validates this?
- What framework operationalizes this?
- What framework competes with this?
- What framework replaces this?
- What framework explains this?

## Canonical Distinction

```text
Asset
  -> Publishable Knowledge Asset
      -> Framework
      -> Capability
      -> Outcome
      -> Policy
      -> Control
      -> Requirement
      -> Evidence
      -> Benchmark
      -> Decision
      -> Action
      -> Certification
      -> Accreditation
      -> Blueprint
      -> Product
      -> Service
```

Framework is a first-class asset type, not the only asset type.

## Framework as Organizing Primitive

A framework is a reusable structure for understanding, deciding, governing, evaluating, or operating something.

Frameworks may organize:

- capabilities
- outcomes
- requirements
- policies
- controls
- standards
- protocols
- evidence
- benchmarks
- implementation patterns
- decisions
- actions
- operating models

## Framework Families

A framework may belong to a framework family.

Examples:

```text
Cloud Native Frameworks
Enterprise Architecture Frameworks
Security Frameworks
AI Governance Frameworks
Data Governance Frameworks
Identity Frameworks
Operating Model Frameworks
Learning Frameworks
Decision Frameworks
```

## Framework Relationships

Frameworks connect to other assets through typed relationships:

- enables capability
- supports outcome
- satisfies requirement
- implements standard
- uses protocol
- governed by policy
- verified by control
- validated by benchmark
- supported by evidence
- produces decision
- guides action
- realized through product or service

## Anti-Flattening Rule

Do not collapse every asset into `Framework`.

Use `Framework` when the asset is a reusable structure, model, method, architecture, standard set, governance system, or evaluation pattern.

Use more specific asset types when the object is a capability, outcome, policy, control, decision, evidence item, metric, product, service, certification, or accreditation.

## Publishing Rule

Every publishable asset must declare its framework context.

```yaml
framework_context:
  primary_framework:
  framework_family:
  related_frameworks:
  relationship_type:
  rationale:
```

## Platform Rule

The platform should let users start from any of these entry points:

- framework
- capability
- outcome
- policy
- control
- product
- benchmark
- decision

But it should always be able to map the user back into the framework graph.

## North Star

OpenFrameworks is not merely a catalog of frameworks.

It is a framework-centric publishing, governance, trust, and decision system for all reusable institutional knowledge assets.
